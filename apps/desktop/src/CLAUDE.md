# src — React webview

React 19 + TanStack Router + [urql] (GraphQL) + Vite + Tailwind v4. UI primitives from `@kubetail/ui`. Package manager is **pnpm**. Path alias: **`@/*` → `src/*`**.

## Security invariants

The whole picture is [`docs/security-model.md`](../docs/security-model.md). What an ordinary change here can break:

- **Anything running in the webview holds the full cluster surface, and the shell behind it.** `graphql_query` forwards operations unexamined, so executing code can call every mutation, `approvalDecide` included. The CSP in `src-tauri/tauri.conf.json` is the containment — never widen `script-src`/`connect-src` to a remote origin, never load a script the bundle doesn't ship.
- **The approval request is the user's eye, and the eye is the whole gate.** `ApprovalRequest` (`chat-transcript/transcript.tsx`) draws exactly what will run — the command, path, content, edit strings, URL and host, memory name and body, or a cluster change's classified action, diff and request — with every invisible or reordering character spelled out (`VisibleText`) and long content folded behind a button Approve waits on. **Approve is a click on that drawn request and nothing else**: no keyboard shortcut, no default button, no approving from anywhere the request is not shown, no "always allow" for a raw command. Duration rules (*Allow for this command* / *this chat* / *Always allow*) are offered for a classified action alone, only where a grant can lift the verdict, armed as Approve is. A request whose action the UI cannot draw offers Deny alone. Adding any approval path is a security change → [the bash tool](../docs/security/2026-09-18-bash-tool.md), [the prompt names the action](../docs/security/2026-10-04-the-prompt-names-the-action.md).
  - **What runs unasked**: a command the sandbox confines; `Write`/`Edit` in the chat's workspace or a read-and-write granted folder; `Read` in a granted folder → [Bash runs in a sandbox](../docs/security/2026-09-28-bash-runs-in-a-sandbox.md), [path grants](../docs/security/2026-10-04-path-grants.md). A confined command wanting network the chat's switch and the turn's toggle don't give is its own request; the switch and toggle are the user's clicks alone, the switch behind a confirm (the composer draws no toggle yet, so a send carries it off) → [network is the user's switch](../docs/security/2026-10-04-network-is-the-users-switch.md).
  - **A grant is the user's act alone** (Settings, or `folderGrant`); a way for the model to make one is a security change.
  - Each change a sandboxed command sends to a cluster or a cloud platform, and each read of Secret data or a cloud object's contents, runs, asks or is refused per its account's mode and the rules; Secret data passes `[redacted]` unless allowed. What no table names, a destructive change and an access control change outside a namespace ask each time → [one engine for every target](../docs/security/2026-11-25-target-neutral-permissions.md), [cluster writes ask](../docs/security/2026-09-29-cluster-writes-ask.md), [the permissions engine](../docs/security/2026-10-02-the-permissions-engine.md), [Secret data is a permissioned read](../docs/security/2026-10-05-secret-data-is-a-permissioned-read.md).
  - A subagent's request is the same request, opening with *An agent asks:* and its `Agent` call's description → [the Agent tool](../docs/security/2026-09-25-agent-tool.md).
  - **Requests are drawn whether or not an answer streams, several at once, in the order asked**; buttons are live on a `Pending` approval while the message's `awaitingApproval` holds; **Approve arms only after its place on screen holds still for `APPROVE_ARM_MS` (500ms)**, re-arming on any move. The composer's *Show* and the chat list's dot point to a request and never approve one → [background agents](../docs/security/2026-09-25-background-agents.md).
- **The model's description of a command is its claim, never the app's.** One line, through `VisibleText`, italic, labelled *The model says:* and quoted on the request, never in place of the command there and never brighter than it → [the command description](../docs/security/2026-09-23-the-command-description.md). A settled call's row draws it bare after the call's kind, with the command in the call's body → [a settled call reads by its kind](../docs/security/2026-11-15-a-settled-call-reads-by-its-kind.md).
- **Cluster data is attacker-controlled text.** `src/` has no HTML sink — no `innerHTML`, `dangerouslySetInnerHTML` or `eval` — and `kubetail/no-restricted-syntax`, `react/no-danger` and `no-restricted-imports` in `.oxlintrc.json` fail the lint on one, and on a template engine by import or call. Printer columns go through the restricted reader in `src/lib/jsonpath.ts`. A tooltip can't mark a spelled character, so a `title` holding cluster data takes `visibleTitle` (`src/lib/visible-text.ts`).
- **A chat answer inherits this.** `markdown/markdown.tsx` renders to React elements with raw HTML left as text; no rehype plugin may put HTML back.
- **The log viewer and the exec window inherit this.** Output is untrusted bytes: no HTML interpretation, terminal control sequences stripped. The sidecar strips each log line of every control but its SGR sequences (`services/logs`), and the viewer draws every cell through `VisibleText`, the message's colours through `AnsiText` (`components/logs/ansi-text.tsx`: fancy-ansi's escaped output, parsed in an inert `DOMParser` document and read back as styled runs, never inserted). Copy writes a message without its sequences. The exec window, when it lands, brings both. → [log lines keep their colours](../docs/security/2026-10-19-log-lines-keep-their-colours.md).

## Routing & layout

- Entry: `src/main.tsx` → `RouterProvider`. Routes in `src/routes/` (code-based, wired in `src/routeTree.ts`): `__root.tsx` mounts the provider stack; `_app.tsx` is a pathless layout rendering `AppLayout`; `chat.tsx` (`/chat`), `chat-id.tsx` (`/chat/$chatId`) and `dashboard.tsx` nest under it. `index.tsx` redirects to `DEFAULT_ROUTE`. `_logs.tsx` is a second pathless layout, rendering `LogsWindowLayout`, with `logs-window.tsx` (`/logs`, the page every `logs-N` window loads) under it. **The chat id is a path param, not a search param** — `retainSearchParams` on `_app` would drag a search param into the dashboard. The Chat/Dashboard switch is the omnibox's tabs (router `Link`s).
- **Layouts** (`src/layouts/`) are presentational shells rendering an `Outlet`. `LogsWindowLayout` is the log window's: one column the window's height bounds, no sidebars, no dialogs host; its page draws its own bar.
- App-wide concerns live in `src/lib/`; components in `src/components/`.
- **A file in `src/lib/` holds one concept, not one export.** A single export joins the module that owns its concept (`approvalAnchor` in `chats.tsx`; the looks areas share, in `control-style.ts`). It keeps a file of its own only when several areas name it and none owns it (`app-mode.ts`, `storage-key.ts`).
- **A length of time is drawn by `humanDuration`** (`src/lib/human-duration.ts`), as kubectl prints one: `83s`, `5m7s`, `3h20m`, `3d`. A caller adds wording around it (*in 90s*, *45s ago*), never a formatter of its own. `humanMinutes` is the same by the whole minute, for a span drawn beside one that ticks each second (the cluster's uptime). One that ticks is drawn through `Elapsed` (`primitives/elapsed.tsx`), which `RelativeTime` and `Countdown` word.
- **A component under `src/components/` is a `.tsx` file or a folder exporting one React component, used on a page or inside a higher-level component.** A component in one file is a file in its area folder (`dashboard/status-pill.tsx`). A component with parts is a folder whose `index.ts` exports that component and its prop types alone; nothing outside imports a part, except a test's `vi.mock` of the part's file and a CSS side-effect import. A part's file does not repeat its folder's name (`left-sidebar/panel.tsx`). Code that is not a component (hooks, pure functions, shared types) lives in `src/lib/`. `log-cards/` is the one family: it exports the transcript's three cards.
- **Each component sits in one of seven area folders:**
  - `primitives/` — components that know no feature concept: text, inputs, dialogs, section headings, Markdown, resize handles, times, the app mark, the window frame and its controls. The test: it would make sense in an app with no clusters or chats.
  - `cluster/` — the cluster picker, status popover, sync panel, dot, TLS badge, data-rate sparkline, memory list and instructions.
  - `logs/` — the log viewer, the log panel, the log window, a view's source line and `AnsiText`.
  - `settings/` — the settings dialog and the folder-grant form.
  - `chat/` — the chat panes, title bar, composer, transcript, nav, the transcript's log cards, and the dashboard's chat.
  - `dashboard/` — the objects and events tables, the object panel, the resource nav, the breadcrumb bar, the page header, the status pill and `VirtualTable`.
  - `shell/` — the app bar, the context omnibox and mode tabs, both sidebars, the app's dialogs host, the startup gate, the error boundary and the error banner.
- **Imports point one way**: `primitives` ← `cluster` ← `logs` ← `settings` ← `chat`, `dashboard` ← `shell`. An area imports only from the areas to its left (and `src/lib/`); `chat` and `dashboard` import neither each other. Across areas an import is `@/components/<area>/<name>`; a sibling in the same area may use `./`.

## Errors reach the host's log

`reportError` (`src/lib/error-bus.ts`) is the one producer; `src/lib/error-log.ts` is the sink: `startErrorLogForwarder` sends each record to the host's `webview_record_error`, and `installGlobalErrorHandlers` reports `error`/`unhandledrejection` as `render`. Both are called in `main.tsx` **before `createRoot`**. A module that throws while loading is not covered. **`errorReportExchange` forwards every GraphQL operation error**, so a component never calls `reportError` for one.

- An `AppError`'s `context` holds **explicitly chosen keys, never a serialized `cause`** — a `CombinedError` holds GraphQL payloads full of cluster text.
- The forwarder reads each field under its own guard (a getter can throw), caps strings, swallows a rejected invoke, and **never calls `reportError` on failure** (that would loop).
- Sends past `MAX_IN_FLIGHT` are dropped, `RESERVED_IN_FLIGHT` slots kept for `render`/`auth`; the drop count rides as `context.dropped` on the next record.
- The host is the authority on caps and rate limits (`src-tauri/CLAUDE.md`, Logging).

## Window state

`kubeContext`, `resource`, `namespace` and `chat` are search params on `_app`, kept across mode switches via `retainSearchParams` — per-window, deep-linkable, history-pushing. → [ADR: URL params as window state](../docs/adr/2026-08-09-url-params-as-window-state.md). Accessors: `useActiveKubeContext` (`src/lib/active-kube-context.tsx`; falls back to `KubeConfig.defaultContext`; `setContext` writes the param, never the kubeconfig; `useFixWindowContext` fixes it there) and `resolveDashboardResource`. `chat` is the dashboard panel's open chat, read by `DashboardChat` alone. `namespace` is the dashboard's namespace scope, absent for every namespace, read and written through `useNamespaceScope` (`src/lib/namespace-scope.ts`); only the dashboard reads it, and the omnibox's cluster switch clears it with `chat`. **The cluster is the window's one high-level scope**; everything else follows from it. → [ADR: the cluster is the app's scope](../docs/adr/2026-09-11-the-cluster-is-the-apps-scope.md), [ADR: the dashboard's namespace scope is a search param](../docs/adr/2026-11-12-the-namespace-scope-is-a-search-param.md). **Links writing one param must spread the previous search** (`(prev) => ({ ...prev, resource })`).

**The window's shape** is `layouts/app-layout.tsx`: a 56px app bar over an inset box of the left sidebar, `<main>` and the right sidebar (the shell guide). Chrome — sidebar widths and open flags, the focused log view (`useLogsView`), the focused object (`useObjectView`) — stays out of the URL, so Back and Forward leave it alone.

**The layout bounds the scroll, and the window never scrolls.** `html` is `overflow: clip` (`index.css`), so a wheel outside every scroller moves nothing. The chain is `h-(--app-min-h) min-h-0` on the `SidebarProvider` column, `min-h-0 flex-1 overflow-clip` on the content row, the inset box (its items' minimum widths can outgrow a narrow window), `min-h-0 flex-1 overflow-hidden` on `<main>` (all in `app-layout.tsx`), `flex min-h-0 flex-1 flex-col` on the route's `<section>`, then the table's `flex-1 overflow-auto`. Traps:

- `min-h-0` goes on every *plain* flex item between frame and scroller, never on the scroller itself.
- It must stay beside `h-` on the provider: only `min-h-*` displaces the library's hardcoded `min-h-svh` via tailwind-merge, and on Linux `--app-min-h` (100% of the `WindowFrame` inset) is shorter than `100svh`.
- That percentage is definite only while every DOM ancestor is — one wrapper `<div>` between `WindowFrame` and the provider breaks it.
- Any other scrolling route under `_app` needs `min-h-0` on its own chain (`chat.tsx` via `CenteredColumn`).
- Tests that render rows call `stubLayout()` from `@/test-utils`; jsdom has no layout, so a virtualized table renders none.

## Theming & storage

**Browser-storage keys are `kubetail:`-prefixed kebab-case, formed only by `storageKey`** (`src/lib/storage-key.ts`). Call sites pass the bare name. `@kubetail/ui` writes its own unprefixed `sidebar_state` cookie. Browser storage holds chrome shape (pane widths, open flags) and the history ceiling; a user *setting* goes to `host.json`.

**Every window shares one `localStorage`; each has its own `sessionStorage`.** Chrome shape (`usePersistedWidth`, `usePersistedFlag`) is an app-wide default with no live sync: the next window opens the way the last was left. The history ceiling is per-webview and lives in `sessionStorage`. → [ADR: chrome shape is an app-wide default](../docs/adr/2026-10-17-chrome-shape-is-an-app-wide-default-in-localstorage.md). Every `kubetail:*` key is *disposable* in [`docs/persisted-data.md`](../docs/persisted-data.md): a bad value reads as the default, and a new or changed key updates its register row in the same commit.

`src/lib/theme.tsx` has two axes: **color scheme** (`system`/`light`/`dark` → `.dark` on `<html>`, whose `color-scheme` in `index.css` draws the webview's own scrollbars and controls to match) and **skin** (reserved). The preference lives in `host.json` (`src/lib/host-file.ts` owns read/update/subscribe), never localStorage. Boot is synchronous via `window.__KUBETAIL_HOST__` and the inline script in `index.html`, which **hand-mirrors `resolveColorScheme`**; its boot mark shows the light or dark app icon by the `.dark` class, as `AppMark` does, pinned by the root `index.test.ts`. Keep both in sync. → [ADR: host.json settings](../docs/adr/2026-08-09-host-json-settings.md), [ADR: first-paint theming](../docs/adr/2026-08-09-first-paint-theming.md). The picker is `settings-dialog/color-scheme-picker.tsx`.

## Text boxes

**Every text box turns off the webview's autocomplete, autocorrect, autocapitalize and inline predictions** (`writingsuggestions`, WebKit's). Draw one with `Input`, `Textarea` or `SearchBox` from `components/primitives/text-entry.tsx`, never `@kubetail/ui`'s (the lint refuses that import). Prose (the chat composer, a chat title, memory bodies and instructions) passes `prose` and keeps spellcheck; code-like text (a grep, a path, a name, a pattern) has it off. A raw `<input>`/`<textarea>` spreads `CODE_TEXT` or `PROSE_TEXT` from the same file. Each box's test pins its set with `expectCodeText`/`expectProseText` from `@/test-utils`. **A text box marks focus by its border alone, never a ring**: browsers match `:focus-visible` on a click into a text box, so a ring would show on every click. The primitives turn the library's ring off; a raw box sets `outline-none focus-visible:border-ring`. Other controls keep the library's keyboard-only ring.

## Cursors

**Controls and in-app links use the default arrow cursor, as native desktop apps do.** `index.css`'s base layer sets it on `button`, `[role="button"]` and `a[href]`, overriding `@kubetail/ui`'s `cursor: pointer` and the browser's hand on links. Every link today is in-app navigation (the sidebar, the mode switch, the chat list). Never add `cursor-pointer` to a button, menu item, tab, link, `<summary>` or popover trigger; only a link that leaves the app may take it.

## GraphQL — never talks HTTP directly

The webview has **no network access**. urql routes everything through Tauri IPC (`src/lib/graphql/`): queries and mutations via `invoke('graphql_query')` (`invoke-fetch.ts`), subscriptions via `graphql_subscribe`/`graphql_unsubscribe` over a Tauri `Channel` (`subscribe-exchange.ts`, with its own capped-backoff reconnect). Read `src/lib/graphql/client.ts` and its tests before touching transport or retry logic. → [ADR: GraphQL over Tauri IPC](../docs/adr/2026-08-09-graphql-over-tauri-ipc.md).

**A `next` frame marked `extensions.subscriptionFailed`** is the sidecar naming why a watch died. `subscribe-exchange` sends it down the drop path (report, hold last-known data, reconnect), never to the urql sink, which would re-deliver the last frame's data. **Key on the marker, never on shape**: a live frame with a field error looks the same. A reconnect dials with the operation's variables, or with what its context's **`reconnectVariables`** answers — `logsTail` hands one in to resume past the newest line it handed on of each container. → [ADR: watch-failure reporting](../docs/adr/2026-08-14-watch-failure-reporting.md).

**Connection lifecycle is the transport-status registry** (`transport-status.ts`): `connected` and a process-wide monotonic `generation`, bumped on the host's **`open` frame**, never on the `graphql_subscribe` ack. Consumers use **`useFoldedSubscription`** (`use-folded-subscription.ts`), never raw `useSubscription`; it generation-gates its accumulator. urql shares one connection per query + variables, so a consumer mounting into a running stream never sees its snapshot. Where a watch has several consumers and one can mount late, either hold the one watch in a provider above them all (`ClusterCachedDataKindsProvider`) or set **`unshared: true`**, which costs a connection and a cold list per instance, so it is not the default. `subscriptionPhase(snapshotComplete, connected)` gives `connecting` (no snapshot yet), `live`, `reconnecting`. A reconnect masks the data until its new snapshot lands. `useChats` holds its last synced list through the replay, each record replaced as it lands; a view that must stay mounted through another watch's reconnect holds what it reads with `useLastSettled` (`use-last-settled.ts`). → [ADR: transport-status generation](../docs/adr/2026-08-09-transport-status-generation.md).

**Frames are reduced as a batch**, once per `requestAnimationFrame` or after 250ms, whichever is first. The reducer gets `frames: Data[]` (never empty). A map reducer copies once per batch and applies frames in place; a simple per-frame fold is lifted with `perFrame(step)`. **Each subscription contract folds through its own reducer** in `src/lib/graphql/` — `collectionWatchReducer`, `stateWatchReducer`, `keyedStateWatchReducer`, `eventFeedReducer`, `sampleFeedReducer` — and a provider calls the one for its contract rather than writing its own. Each returns `snapshotComplete` once the first delivery has arrived. An operation is named for its field, Pascal-cased; its document constant adds `Document`; a hook serving the operation alone is `use` plus its name. → [`docs/data-access.md`](../docs/data-access.md). A frame from a newer connection drops the pending batch. A test that pushes a frame and asserts on the next line calls `flushSubscriptionsSynchronously()` from `@/test-utils` at module scope. → [ADR: batch per animation frame](../docs/adr/2026-08-30-batch-watch-frames-per-animation-frame.md).

## Codegen — generated types, don't hand-write

`pnpm codegen` (`codegen.ts`) reads the **sidecar's** schema (`sidecar/graph/schema.graphqls` — single source of truth) and emits `src/gql/`.

- Write operations with the **`graphql()` tagged template from `@/gql`**.
- **`src/gql/` is generated — never edit it.** After changing a query or the sidecar schema, run `pnpm codegen` (or `pnpm codegen:watch`).

## Tests

Vitest + `@testing-library/react` (jsdom), co-located (`*.test.ts[x]`), under the root `CLAUDE.md`'s *Testing conventions*. Mock the Tauri bridge with **`mockTauriCore()` from `@/test-utils`** (+ `vi.mock('@tauri-apps/api/core', …)` and dynamic import of the module under test). For GraphQL-driven components, push frames via `liveChannel().onmessage!(...)` — see `src/lib/graphql/use-folded-subscription.test.tsx`.

- Workers run with `--no-experimental-webstorage` (`vite.config.ts`): Node's own `localStorage` would shadow jsdom's.
- Run: `make test-changed` while working; `pnpm test --run` (or `make test-ts`) for the whole suite. Watch: `pnpm test`.
- **Coverage is measured in `coverage / TypeScript (linux)`** and gated by `coverage / Gate` (root `CLAUDE.md`, *Testing conventions*). A line no test can reach takes `/* v8 ignore next -- <reason> */`, in a component as anywhere. Coverage runs as `vitest run --mode coverage`, which loads no React compiler, so markers survive and the compiler's cached branches are not measured. A test of re-renders fails there if it passes only through the compiler: memoize by hand where the re-render is the code's own promise (the log row's cells, the transcript's rows), and test no re-renders elsewhere. → [ADR: TypeScript coverage is measured without the React compiler](../docs/adr/2026-10-30-typescript-coverage-is-measured-without-the-react-compiler.md). Exclusions are in `vite.config.ts` and `.github/codecov.yml`'s `ignore` (`src/gql/`, `routeTree.ts`, `main.tsx`, `test-utils.tsx`). `make cover-ts` prints the per-file numbers.

## Lint / build

- `pnpm lint` (oxlint, then `oxfmt --check`) → `make lint-ts`. Run before committing. `pnpm format` writes, sorting imports too. → [ADR: lint the webview with oxlint's categories](../docs/adr/2026-11-05-lint-the-webview-with-oxlints-categories-and-a-chosen-rule-list.md), [ADR: oxlint's native React compiler rules](../docs/adr/2026-11-05-lint-the-react-compilers-rules-with-oxlints-native-ports.md)
- **Linting is oxlint** (`.oxlintrc.json`): the `correctness`, `suspicious` and `perf` categories, rules from the other categories named one by one, and type-aware rules through `oxlint-tsgolint`. A rule an enabled category already turns on is listed only to give it options or turn it off, with the reason beside it. **Every rule is an error and a warning fails the run.** Kubetail's own rules are `lint/oxlint-plugin.js`, tested in `lint/oxlint-plugin.test.ts`.
- **Tailwind classes are `pnpm lint:tailwind`** (`.oxlintrc.tailwind.json`, `make lint-tailwind`), a run apart from `pnpm lint` because loading Tailwind takes most of its ~6s. It checks `className` and `cn(...)` against `src/index.css`'s design system: the canonical spelling (`wrap-break-word`, not `break-words`; `size-4`, not `h-4 w-4`), no class Tailwind does not know, and no two classes setting the same property. `pnpm lint:tailwind --fix` rewrites a spelling. A class string built anywhere else is not checked. Order and wrapping are `oxfmt`'s. **Run it after changing classes.** CI's `Lint · TypeScript` runs it. → [ADR: lint Tailwind classes in a run of their own](../docs/adr/2026-11-05-lint-tailwind-classes-in-a-run-of-their-own.md)
- **What the rules ask for**: no `any` and no value typed `any` outside tests; `toSorted` and `toReversed`, never a `sort` or `reverse` in place on an array others hold; `??` for a nullish default, `||` where an empty string or `false` should fall through; a default prop that is an object, array or function is a module constant. `for…of` is allowed, `for…in` is not.
- **A switch over a union lists every member** and needs no `default`; a `default` does not stand in for a missing one. Any other switch has a `default`.
- **`tsc` checks fallthrough, implicit returns and `import type`** (`noFallthroughCasesInSwitch`, `noImplicitReturns`, `verbatimModuleSyntax`); the lint has no rule for them.
- **A disable comment is `oxlint-disable…` and gives its reason**: `// oxlint-disable-next-line <rule> -- <why the rule is wrong here>`. `kubetail/disable-needs-reason` fails one without, an unused one fails, and `eslint-disable` comments are not read.
- **A promise nothing awaits is marked `void`** (`typescript/no-floating-promises`): an urql mutation or a `navigate` fired from a handler, for example. A JSX handler may return one.
- **Formatting is oxfmt** (`.oxfmtrc.json`), which also sorts imports: packages, `@/`, then relative paths, a blank line between. The `lint`/`format` scripts pass **globs only**: a directory argument mixed with a glob silently narrows to the glob's extensions. `.vscode/settings.json` runs the same binaries in the editor (`oxc.oxc-vscode`, resolved from `node_modules`).
- The **React compiler** is on in two places that must stay in step: the babel transform (`vite.config.ts`, off in `--mode coverage`) and oxlint's native ports of the compiler's rules (`react/purity`, `react/refs`, `react/exhaustive-deps`, …: `recommended-latest`'s set, in `.oxlintrc.json`). A disable comment names them `react/…`. A bail-out on a broken rule is a lint error; one on syntax the compiler does not support yet (`react/todo`, such as `??=`) is silent.
- **Write as though the compiler weren't there** — it bails per-function, silently. So `react/exhaustive-deps` is an **error**, and manual `useMemo`/`useCallback` are ordinary tools.
- In the Linux sandbox a package resolves only the dependencies it declares, so an error seen only there is most likely an undeclared dependency (root `CLAUDE.md`, *Building inside a Linux sandbox*).
- **An `*.svg?react` import is a React component** drawing the SVG inline (`vite-plugin-svgr`, in `vite.config.ts`); a plain `*.svg` import is a URL.
- `pnpm build` = `tsc -b && vite build`. Dev: `pnpm dev` (webview) or `pnpm tauri dev` (full app).
