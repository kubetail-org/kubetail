# src/components/settings — the settings dialog

The settings dialog and the folder-grant form. Also owns `src/lib/`'s `sandbox-*.tsx`, `cluster-scope.ts`, `env-vars.tsx`, `permission-settings.tsx`, `permission-pattern.ts`, `provider-credentials.tsx`, `tool-settings.tsx` and `settings-tab.ts`. The webview-wide rules, security invariants first, are [`src/CLAUDE.md`](../../CLAUDE.md), which also covers the color-scheme picker (*Theming & storage*).

Every data access here is named for its contract: [`docs/data-access.md`](../../../docs/data-access.md).

**The Settings dialog** is `components/settings/settings-dialog/`, exporting `SettingsDialog` alone: a `PanelDialog` (`primitives/dialog.tsx`) with vertical tabs beside its pane. It opens on General (`general.tsx`), which holds the Mode picker (`color-scheme-picker.tsx`). A pane is a column of `Group`s (`group.tsx`): a heading, optional lede, info control (`InfoPopover`) and action, over its body. A pane that is one list is an `Intro` instead: its lede over the list, which the pane's heading names. A hidden tab's pane unmounts, so its watches run only while it is selected. A pane selects another tab through `useSelectSettingsTab()` (`src/lib/settings-tab.ts`).

**Clusters** (`clusters.tsx`) lists `useClusters()`'s kubeconfig clusters, then the archived ones (no longer in the kubeconfig), hidden when there are none; nothing draws before the `Bookmark`. Every string from a cluster goes through `VisibleText`. Its actions are `ClusterSyncPanel`'s mutations (`src/lib/cluster-mutations.ts`), with no confirm, and *Set as default* / *Remove as default* on an enabled present row; the default's row has a *Default* badge, archived or not. Each row redraws from the watch.

**Connectors** (`connectors.tsx`) is one list, by name, of `useConnectors()`'s services (`src/lib/connectors.tsx`), drawing nothing before each watch's first frame. **ChatGPT, OpenRouter, AWS, GitHub and Google are real rows**, their actions following the connection's phase. A `Restoring` row draws `CHECKING_KEYCHAIN`, no action; OpenRouter's signed-out detail does too while its provider restores. `failureText`, a `Record` over `ConnectorFailure`, gives each failure its line, so a new one fails the build. ChatGPT's first connection is confirmed once, in the window that connected (`kubetail:chatgpt-plan-confirmed`; the window's pending sign-in is `sessionStorage`'s, so it outlasts the pane). Disconnect is confirmed: OpenRouter's and GitHub's credential stays live there, AWS's session until it expires. AWS's detail is the ARN; GitHub's draws its code. The other rows are placeholders: a connected one with a disabled menu, any other with a disabled *Coming soon*. Every string goes through `VisibleText`.

**Providers** (`providers.tsx`) lists `useProviderCredentials()`'s providers, set up while signed, then `PROVIDERS`, set up while `useModels()` serves them; nothing draws before both. Null `keyVariable` gets *Connect*, no key UI. `Restoring` is `status: 'checking'`: a dashed ring, `CHECKING_KEYCHAIN`, no action. *Configure…* and *Set up* open `provider-setup-form.tsx`. **The webview's one typed secret**: the form holds the key, and the hook sends it through `client.mutation(...).toPromise()`, never `useMutation`, whose state would keep it. → [record](../../../docs/security/2026-11-20-saved-provider-keys.md).

**Tools** (`tools.tsx`, `useToolSettings`) is the `toolSettingsStateWatch` in a `Group` per kind, a switch per tool, held on for an `alwaysOn` tool; a row leaves room for the tool's own settings.

**Memory** (`memory.tsx`) shows one scope: *Every cluster* (the default) or a cluster, picked from the kubeconfig's, then the archived, by `ScopePicker` (`scope-picker.tsx`) over `useScope`. It draws `components/cluster/`'s memory instructions and list (`src/components/cluster/CLAUDE.md`, *Memory*), keyed on the scope; it is the one way to memory. Every cluster's notes ride on the window's cluster's watch, else the first record's. Placeholders, marked in code: local instructions, no note counts, and a disabled *Clear* awaiting `memoryClear`.

**Environment** (`environment.tsx`) is the user's variables for one scope (`useEnvVars(clusterID)`), picked as Memory's is. A variable names the commands it reaches (`EnvVarTarget`); a refused one is drawn on its own row with its reason. The form is keyed on the scope.

**Monitoring** (`monitoring.tsx`) is a placeholder, *Coming soon*, until monitoring has settings of its own.

**Sandbox** (`sandbox.tsx`) is the status card (`sandbox-card.tsx`), then one `Group` (`group.tsx`) per section in a file beside it: `sandbox-folders.tsx`, `-network.tsx` (`useSandboxCloudAccess`, read-only), `-path.tsx`, Executables, `-environment.tsx`; *Try a command* opens `sandbox-console.tsx` over `useSandboxConsole`, which folds the `sandboxConsoleStateWatch` into a history by command number; closing it stops a running command. With `available: false`, the card alone, and Permissions says why nothing applies. Placeholders, each disabled or marked *Coming soon*: the status switch, the tools/shell/system folder groups, Environment but *Custom*, which lists every cluster's variables for sandboxed commands (`useEnvVars(null)`) and edits none. A query's hook re-asks it after a mutation, and on focus where another window can change it. Every user, sidecar or command string goes through `VisibleText`.

- **`PATH`** (`useSandboxPath`, shared by Folders' `PATH` group, which lists the searched folders read-only, and the PATH card). The card edits one string, `sandboxPathSet`, with Reset (`$PATH`) and *Import from shell*; a taken save or import probes the executables. A draft hiding a character is drawn again through `VisibleText`: a text field shows none. Add, offered only where `addable`, appends the folder's `target` to the draft, unsaved. A save answered `KUBETAIL_SAVED_UNREAD` took. → [ADR](../../../docs/adr/2026-11-24-the-sandbox-path-is-one-setting-the-user-writes.md).
- **Executables** (`useSandboxExecutables` in `src/lib/sandbox-executables.tsx`) over `sandboxExecutablesStateWatch`. The probe mutation answers at once and the watch carries the end. A refused registered executable draws its `refusal` in place of a probe result. A row is keyed by whether it is registered and its name, since a registered name can be a curated one's. A register answered `KUBETAIL_SAVED_UNREAD` took: the form clears and the message stays. After a press, *Probe again* holds until the watch's `probes` count passes the one seen at the press — the answer and the frame race, and a gauge can fold a short probe's start into its end.
- **Folders** (`useSandboxFolders`, `src/lib/sandbox-folders.tsx`, over `sandboxFoldersStateWatch`). **`FolderGrantForm`** (`components/settings/folder-grant-form.tsx`) is the one form granting a folder, here and in the transcript; it sends the path as typed. A grant's access and Remove depend on no rule: only its own removal in flight holds them. `revoke(id, duration)` names whose grant it is, as `folderGrant` does. → [path grants](../../../docs/security/2026-10-04-path-grants.md).
- **Permissions** (`permissions.tsx`, `permission-*.tsx`; `usePermissionSettings`). A section per target: Kubernetes' default mode, then its clusters (`targets[].accounts` joined onto `useClusters()` by `clusterID`, drawn once the cluster arrives, named by `displayName`); each cloud platform the build offers: its default, its accounts and an add-account form, marked *Off* when `useSandboxCloudAccess` leaves it out. *Clear* returns an account to the default. A rule's scope is built by `src/lib/permission-pattern.ts`, the account a literal; an Allow names a target and an account. **An edit is one `permissionRuleUpdate`, keeping the rule's id and place.** Placeholders: `// Placeholder: awaits …`. → [the permissions engine](../../../docs/security/2026-10-02-the-permissions-engine.md).
