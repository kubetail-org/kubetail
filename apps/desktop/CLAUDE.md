# Kubetail

A Kubernetes desktop app. Three parts that talk to each other:

- **`src/`** — React webview. See `src/CLAUDE.md`.
- **`src-tauri/`** — Tauri/Rust native host (windows, tray, sidecar lifecycle). See `src-tauri/CLAUDE.md`.
- **`sidecar/`** — Go sidecar (GraphQL API, Kubernetes + cloud logic). See `sidecar/CLAUDE.md`.
- **`lint/`** — Kubetail's own oxlint rules (`oxlint-plugin.js`), which `.oxlintrc.json` loads beside the webview's lint config. See `src/CLAUDE.md`, *Lint / build*.
- **`tools/`** — a Go module holding CI's Go tools (`actionlint`, `govulncheck`, `staticcheck`) as `tool` dependencies, so Dependabot moves them. Run one with `go tool <name>` from `tools/`. `tools/releasenotes` collects a release's range from `git` and `gh`, checks the notes against it, renders them and, once the releaser answers on the terminal, writes them to the draft release (`go run ./releasenotes`). `tools/securitymodel` checks the security model against the tests and files it cites (`make lint-security-model`, part of `make lint` and CI's `Lint · Security model` job) and writes its index and register (`go run ./securitymodel write`). `tools/designsync` checks the design manifest and lists the components and screens whose code or design moved, reading Figma over its REST API when `FIGMA_TOKEN` is set (`go run ./designsync`; `design/CLAUDE.md`).
- **`.claude/skills/`** — the repo's Claude Code skills. `release-notes` (`/release-notes desktop <tag>`) writes a draft release's notes over `tools/releasenotes`; GitHub Releases is the changelog, and `CHANGELOG.md` only points to each product's releases. Each product's paths are its `release-<product>` filter in `.github/ci-config/path-filters.yml`. → [ADR: write release notes with a skill over deterministic tooling](../../docs/adr/2026-11-10-write-release-notes-with-a-skill-over-deterministic-tooling.md).
- **`design/`** — how the webview's design in Figma maps to `src/`: the guide to syncing them in either direction, `components.json`, the manifest joining each Figma component and screen to its source, and the script that writes each one's stamp in Figma. `make lint-design` checks the manifest, as part of `make lint` and CI's `Lint · Design` job; `make design-status` lists what is out of sync. See `design/CLAUDE.md`.
- **`src-icons/`** — the icon masters (SVG). `app-light.svg` and `app-dark.svg` are full-size: the Windows/Linux app icon and the webview's `AppMark`. The `-macos` masters are macOS's alone: `app-macos.svg` (Apple's grid, an 824px square on 1024) for `icon.icns`, and `tray-macos.svg` (full-size, since tray-icon fits the image to 18pt) for the template tray. `make generate-icons` generates `src-tauri/icons/`, `public/favicon.ico` and the webview's copies in `src/assets/icons/`; edit only the masters.
- **`licenses/`** — the licenses and `THIRD_PARTY_NOTICES.md` of the third-party programs the Linux packages carry (bwrap, pasta, the AppArmor profiles), installed with them. Kubetail's own `LICENSE` stays at the root. See `licenses/README.md` and `src-tauri/linux/CLAUDE.md`.
- **`proto/`** — shared gRPC contract (host↔sidecar). Single source of truth, compiled to Go (committed, via `protoc`) and Rust (via `src-tauri/build.rs`). Run `make generate-proto` after editing. `sidecar/internal/app/layout/testdata/layouts.json` pins the folder layout both sides compute.

The **`Makefile` is the polyglot entry point**. Each target is `<verb>` for every area or `<verb>-<area>` for one (`lint-go`, `vet-rust`, `test-ts`, `build-sidecar`), and `make help` lists them with their descriptions (the `##` after each target). `make check` runs `lint`, `vet` and `test`. `make cover-go` and `make cover-ts` print this machine's coverage, `make cover-changed` the changed lines it leaves uncovered. `make lint-tailwind` checks the webview's Tailwind classes, apart from `make lint-ts` for its time (`src/CLAUDE.md`, *Lint / build*). `make lint-md` checks tracked Markdown's local paths and anchors offline, and is part of `make lint` and CI's `Lint · Markdown` job. `make lint-claude-md` checks tracked `CLAUDE.md` byte budgets locally and in CI’s `Lint · CLAUDE.md` job. The Go sidecar lives outside `package.json`. Its build is `scripts/build-sidecar.go` (`make build-sidecar` runs it); `tauri dev`/`tauri build` call it with `go run`, never `make` or `sh`, because on Windows Tauri runs them through `cmd.exe`. Other recipes may be `sh`. Environment variables that change a dev run are listed in [`docs/development-switches.md`](docs/development-switches.md). `make clean-data` deletes the dev app's data, cache, config and state folders (refuses while a dev sidecar runs; `sidecar/scripts/clean-dev-data.go`); `make clean` deletes only its saved window frame.

**Automatic workflow runs happen only in `kstackhq/kstack`.** GitHub starts `push`, `schedule` and `issues` runs in forks too, so every job such an event can start carries an `if:`. CI's workflows gate on `github.repository == 'kstackhq/kstack' || github.event_name == 'pull_request' || github.event_name == 'workflow_dispatch'`, so a fork's PR or dispatch still runs; the release and issue workflows gate on the repository alone. The check sits once per workflow, on the job every other job needs: `Plan` (`changes`) in `ci.yml`, `coverage.yml` and `codeql.yml`, a `fork-gate` job in `audit.yml`, and `stress.yml`'s one job itself; a job whose `if:` uses `always()` or `!cancelled()` checks that its needs succeeded too. A new workflow follows the same rule.

**A job's `name:` is `<Verb> · <Qualifier> (<matrix values>)`**: `Lint · Rust`, `Build · Sidecar (linux, arm64)`. The qualifier tells same-verb jobs apart; `ci.yml` covers every language, so its jobs keep it, unless a verb has one subject (`Staticcheck`). Matrix values are values only, from OS to arch to variant; GitHub appends them to a name with no `${{ }}` expression. A single-purpose workflow drops the verb (`codeql / Go`). `Plan`, `Gate`, `Fork gate`, `Prune · Caches` and `Report · Failures` are fixed. Change only `name:`, never a job id. → [ADR: name workflow jobs verb first](../../docs/adr/2026-11-19-name-workflow-jobs-verb-first.md)

**Building inside a Linux sandbox (macOS host).** `scripts/sandbox-dev-setup.sh` **must run before any build, test, or install command**. A `SessionStart` hook in `.claude/settings.json` runs it; it is idempotent, so run it yourself if unsure. It keeps Linux build outputs out of the host's paths, so a `pnpm install` here does not overwrite the host's macOS native binaries. Cargo's `target/`, one pnpm store and each worktree's `node_modules` go on the sandbox overlay under `/home/agent/kubetail-build`; `dist` stays on the host disk under `.sandbox-linux/`. pnpm uses its global virtual store there, so a worktree's `node_modules` holds only symlinks into the shared store: **never edit a file under it**, since every worktree shares it. If something fails only in the sandbox, unset `PNPM_CONFIG_ENABLE_GLOBAL_VIRTUAL_STORE`, empty `node_modules` and reinstall to rule out the layout. Dev builds there set `CARGO_PROFILE_DEV_DEBUG=line-tables-only`, as CI does, to keep `target/` small. It pins Go to CI's version, the `go-version` default in `.github/actions/setup-environment/action.yml`, by writing `GOTOOLCHAIN=go<version>+auto`; rerun it after bumping that default. The image's `uv` aborts on a 16 KiB-page host (Apple silicon), so when `uv --version` fails the script pip-installs its pinned `UV_VERSION` into `~/.local/bin`, ahead of `/usr/bin` on `PATH`; `make lint-yaml` needs it. It reinstalls rustup's `llvm-tools` (for `RUST=1 make cover-changed`) when a raced install left it half-installed: registered with no files, or files with no registration. The overlay is 20G and tight: the script warns under 2G free. After the script remounts `node_modules`, run `pnpm install`. It no-ops outside the sandbox. → [ADR: keep the sandbox's build outputs off the host mount](../../docs/adr/2026-11-09-keep-the-sandboxs-build-outputs-off-the-host-mount.md). README has the one-time toolchain install.

## Host↔sidecar transport

Host and sidecar share one Unix socket / named pipe. **GraphQL** (webview↔sidecar) rides HTTP/1.1 (POST + SSE); **gRPC** (host↔sidecar control: tray auth state watch, login/logout, resync poke) rides HTTP/2. Both are multiplexed in the sidecar's `internal/app`, served by `net/http` as HTTP/1.1 plus **h2c** (prior knowledge only); no TLS. The cluster surface is **GraphQL-only**. → [ADR: single-socket h2c from the standard library](docs/adr/2026-10-26-single-socket-h2c-from-the-standard-library.md).

**The caches fill.** A reachable cluster whose credentials can read `kube-system` gets a cache; the cache controller arms `kubesync`, which mirrors each served kind into one `ClusterCachedKind` record, and each record arms that kind's sync (cold list, then watch). Every record's `events(...)` field serves its control-plane timeline, as do the event feeds `clusterEventFeed(id: ClusterID!)` and `objectEventFeed(id: ObjectID!)`. → `sidecar/CLAUDE.md`.

**Every data access is named for its contract**: [`docs/data-access.md`](docs/data-access.md) states each contract. A query is a Get, List or Fetch, its field ending in the verb (`envVarsGet`). Cluster data arrives as **collection watches**: an `Added` snapshot, one `Bookmark` closing it, then per-object `Added`/`Modified`/`Deleted` (`clusterCollectionWatch`, `clusterCacheCollectionWatch`, `clusterCachedKindCollectionWatch`). A **state watch** sends the whole value on subscribe and on each change, with no `Bookmark` (`authStateWatch`, `…ConnectionStateWatch`); `clusterCacheHealthKeyedStateWatch` is a **keyed state watch**, one value per `cacheID`. Until the launch has read the keyring, a connection's phase or a provider's source is `Restoring` and `authStateWatch` carries `restoring` ([ADR](docs/adr/2026-11-20-a-launch-restores-keyring-credentials-in-the-background.md)). `clusterDataRateSampleFeed(id)` is a **sample feed**: the whole retained window first, even if empty, then only newer samples; `sampleFeedReducer` keeps the last window ÷ interval samples and reads no times. `logsTail` is a **cursor tail**. The webview folds each subscription through its reducer in `src/lib/graphql/` and **joins client-side**: caches onto clusters by `clusterID`, kinds onto caches by `owner.id`, health values by `cacheID`. **A cluster's id is the `ClusterID` scalar, every other record's is `ObjectID`; the webview never builds or parses either.** Rules for consumers:

- **Never render an empty state before the `Bookmark` lands.**
- **Detect it as `type === 'Bookmark'`, never as a missing entity** — a nested non-null field erroring nulls its parent, so a null entity also arrives on ordinary changes.
- A change with no entity is dropped, not folded.

→ [ADR: name every data access](docs/adr/2026-11-25-name-every-data-access-for-its-family-kind-and-operation.md). The kube-context picker derives its list from `clusterCollectionWatch` (`src/lib/kube-config.tsx`).

**The sidecar never filters what it streams.** A record awaiting deletion arrives carrying `deletionRequestedAt` (an ordinary `Modified`); `Deleted` means its row is gone. `clusterDelete` returns once the row is marked and the teardown follows. **Only the `Deleted` is promised** — a fast teardown folds the mark into it, so never gate a removal on having seen the mark. `ClustersProvider`'s fold folds a tombstoned row as a removal, once, for every view; change that there (e.g. to draw "Deleting…"), never in views.

> **Keep these docs current.** There is a `CLAUDE.md` per area (`src/`, `src-tauri/`, `sidecar/`, `design/`, one per larger sidecar package, listed in `sidecar/CLAUDE.md`, one per webview subsystem, listed in `src/CLAUDE.md`, and the host's, listed in `src-tauri/CLAUDE.md`); this file holds what crosses them. Every `CLAUDE.md` has an `AGENTS.md` beside it pointing to it, so add both when adding a guide. CI enforces the byte budgets in `.github/ci-config/claude-md-budgets.yml`; explain an increase in the commit body. When you change architecture, conventions, commands, or add a pattern worth knowing, update the relevant `CLAUDE.md` in the same change.
>
> **Rationale lives in ADRs, not here.** These files state *what is true now* — invariants, conventions, commands, traps. *Why* a design was chosen, and what was rejected, goes in `docs/adr/` (see [`docs/adr/README.md`](docs/adr/README.md)), linked from here. When a decision changes, write a new ADR, flip the old one's status, and repoint every link in the same commit — a `CLAUDE.md` never links a superseded ADR.
>
> **Security is recorded in two places.** [`docs/security-model.md`](docs/security-model.md) is the threat model and the map, and [`docs/security-model/`](docs/security-model/) states, a file per subject, what is protected now and which tests pin it; [`docs/security/`](docs/security/) holds dated review records, append-only. Gaps live in [`docs/TODO.md`](docs/TODO.md#security); an accepted risk becomes an ADR plus a **By decision** row in the model. When you change a boundary or land a protection, move its row in the same change; `make lint-security-model` fails on a row citing a test or file that is gone. → [ADR](docs/adr/2026-11-25-the-security-model-is-a-file-per-subject-checked-against-the-code.md).
>
> **Persisted data has a register.** [`docs/persisted-data.md`](docs/persisted-data.md) lists every format Kubetail keeps across a restart, with its class, version stamp and pinning test. A change to a persisted format updates its row in the same commit. No release has shipped a format yet, so each store's schema is one `0001_init.sql`; from `desktop/v0.1.0` on, a schema change is the next numbered migration, and a shipped migration is never edited or removed. There is no app-level data migration yet, so the layout under the data and cache roots only grows. → [ADR: each persisted format carries its own version stamp](docs/adr/2026-10-29-each-persisted-format-carries-its-own-version-stamp.md), [ADR: a shipped schema changes only by a new migration](docs/adr/2026-11-08-a-shipped-schema-changes-only-by-a-new-migration.md).
>
> **Keep comments current — describe the present, not the past.** Code comments and these docs describe only the *current* code. **`docs/adr/` is the sole exemption** (append-only history). Don't leave notes about how code *used to* work, what was *renamed from* or *removed*, or which refactor got you here. Drop "used to", "no longer", "formerly", "superseded". Contrasts with *external* systems ("unlike apimachinery's default") are fine.

## Writing standards

Applies to every hand-written file — Go, Rust, TypeScript, Markdown. Not to generated output (`src/gql/`, `sidecar/graph/generated*`, lockfiles).

1. **Code — simple, idiomatic, easy for a human to follow.** Prefer the boring construction. Match the idiom of the file you are in over the one you would pick on a blank page. Cleverness that needs a comment to survive review is usually the wrong trade.
2. **Names — descriptive, idiomatic, consistent with the rest of the codebase,** signatures and schemas included. One concept, one name.
3. **Comments — terse, necessary, easy for a human to read.** Say what the code cannot: the *why*, the invariant, the trap that made this shape necessary. Never restate what the line already says. A comment justifying a choice the code no longer contains is dead weight — state the current design, don't argue against the alternatives you rejected (that is what `docs/adr/` is for).
4. **Documentation — simple, concise, easy for a human to read.** Lead with what is true now. One idea per sentence.

Watch for comments addressed to a *reviewer* rather than a reader opening the file cold; the tell is a comment that spends its length on the option **not** taken.

A new query or subscription takes its contract and name from [`docs/data-access.md`](docs/data-access.md).

A `UserPromptSubmit` hook (`scripts/writing-standards-hook.sh`, wired in `.claude/settings.json`) restates this every turn. Keep its short form in sync with this section.

## Testing conventions (all three languages)

Apply to `src/`, `sidecar/` and `src-tauri/`; each area's `CLAUDE.md` adds its tooling. → [ADR: test conventions](docs/adr/2026-10-17-tests-split-by-platform-take-seams-as-parameters-and-never-sleep.md).

- **While working, run `make test-changed`** (`scripts/test-changed.sh`); **before a pull request, `make check-changed`** (`scripts/check-changed.sh`): in parallel, the linters and vets of the areas the branch changed and `cover-changed`, whose coverage runs are the Go, TypeScript and Rust test runs, then `test-changed` for the suites it leaves out. Its Go vet is `vet-go-changed` (`scripts/vet-go-changed.sh`): `go vet` and `go fix` on the changed packages, on this machine's platform. `ALL_PLATFORMS=1` adds staticcheck and every other GOOS and tag. The `*-changed` scripts run Go with `CGO_ENABLED=0`, so they share one build cache. Push, and let CI check the other platforms: don't reproduce CI locally. The script's header lists what only CI checks. Don't run `make test` or `make check` locally unless asked: CI runs every suite. A new area, or a new linter in `make lint`, joins `scripts/check-changed.sh`'s mapping as well as `.github/ci-config/path-filters.yml`.
- **A PR builds and tests Go and Rust on one runner per OS; a push to `main` runs every runner.** The runners are `.github/ci-config/runners.json`; an entry marked `pull_request` is its OS's PR leg, and a PR leg's job name drops its macOS version (`macos`, not `macos-27`). Vet · Rust runs the PR legs on every event. `gh workflow run ci.yml --ref <branch>` runs every leg on a branch. Every platform split the code has is still checked on a PR: Vet · Go, `scripts/staticcheck.sh` and `scripts/check-go-fix.sh` cover each GOOS, `linux/arm64` (the sidecar's one `GOARCH` split, `seccomp_linux_<arch>.go`, whose filter tests the arm64 AppArmor job runs) and each build tag; a new split joins all three, and `scripts/vet-go-changed.sh`'s `configs`. A push to `main` also builds and tests the desktop host's release profile, on the release's runners (Linux on Ubuntu 22.04). → [ADR: run each OS once on a PR and the other platforms on main](../../docs/adr/2026-11-10-run-each-os-once-on-a-pr-and-the-other-platforms-on-main.md), [ADR: CI checks every platform split](docs/adr/2026-11-10-ci-tests-every-platform-split-the-code-has.md), [ADR: main builds and tests the release profile](docs/adr/2026-11-10-main-builds-and-tests-the-release-profile.md).
- **Every line a PR changes is covered.** CI uploads each suite's coverage to Codecov (`.github/codecov.yml`), which merges them. CI's `coverage / Gate` job (`tools/coveragegate`) reads the merged result after every upload, taking the changed lines from `git diff <base>...<head>` and each line's coverage and both totals from Codecov's stored reports: it fails on a changed line no test reached, annotating it in the diff, and on a total more than 0.1 points below the base. It is not a required check: the reviewer reads it. The coverage jobs and the gate live in `.github/workflows/coverage.yml`, which runs beside `ci.yml` on PRs, pushes to `main` and dispatch, and on a push to `wip/*` too, so each `main` and `wip/*` commit has the report a PR into it is compared with. Both workflows read their language path filters from `.github/ci-config/path-filters.yml`, so a PR that runs a language's tests also measures its coverage. A base with no report fails the gate at once, naming the base. On macOS and Windows the sidecar's untagged pass tests only the packages whose Go files differ from Linux's, so platform code there counts only from its own package's tests. Before pushing, `make cover-changed` (`scripts/cover-changed.sh`, `tools/coverdiff`) lists the changed lines this machine's tests leave uncovered: Go (`sidecar/`) and TypeScript by the diff, Rust's whole suite when `src-tauri/` or `proto/` changed, every Go test with `FULL=1`. It measures one OS, so on Linux it also lists lines only the Windows or macOS tests reach, and it does not check the total. The loop: open the PR, read `coverage / Gate`'s annotations or step summary, add a test that checks the behaviour of each listed line, push until green. → [ADR: gate PRs on changed lines with Codecov's merged result](../../docs/adr/2026-11-09-gate-prs-on-changed-lines-with-codecovs-merged-result.md), [ADR: run coverage and CodeQL on a push to a wip branch](../../docs/adr/2026-11-19-run-coverage-and-codeql-on-a-push-to-a-wip-branch.md), [ADR: measure and gate coverage per area](../../docs/adr/2026-11-19-measure-and-gate-coverage-per-area.md).
- **A line no test can reach is marked with its reason**: in Go, `// coverage:ignore <reason>` at the end of the line a statement or function begins on exempts it whole, body included, and `// coverage:ignore-start <reason>` to `// coverage:ignore-stop` exempts the lines between; in Rust, `// coverage:ignore-start <reason>` to `// coverage:ignore-stop`, each on a line of its own, and a file with no reachable line is listed in `.github/codecov.yml`'s `ignore` with its reason; in TypeScript, `/* v8 ignore next -- <reason> */`, or `start`/`stop` likewise. `tools/coverignore` drops the Go and Rust markers' lines before the upload. `make lint-markers` fails on a marker without a reason. Prefer making the line reachable (inject the failure through a parameter) over marking it.
- **Every test file sits beside the file it covers** (`foo_test.go` / `foo.test.ts`). A test file with no counterpart means the unit is buried in a larger file — split the *implementation* out to match. Exception: a fixtures-only file (`testutil_test.go`).
- **In Go, a platform-specific test goes in a platform-named file** (`foo_unix_test.go`, `//go:build !windows`), **never behind a `runtime.GOOS` check**. Split a partly platform-specific test rather than skip it (`atomicjson`'s `TestSaveCreatesMissingDirs` / `TestSaveIsOwnerOnly`). Unix paths (`/tmp`) and rename-over-open-file belong to the Unix half.
- **A test closes what it opens before it ends.** Windows removes no open file or directory, so a leaked handle fails `t.TempDir`'s cleanup there alone. Close it in a `t.Cleanup` registered after the `TempDir`; wait out a stray goroutine through the unit's test seam (`write`'s `TestWriteSetsTheStamp`).
- **No magic sleeps.**
  - **TypeScript** — `vi.useFakeTimers()` + `advanceTimersByTimeAsync`, `await waitFor(...)`, or a `flush()`/`act` helper.
  - **Go** — wait on a channel: `testutil.Probe`/`Signal`, `testutil.Recv`/`Wait`, or `require.Eventually`. Never `time.Sleep`.
  - **Rust** — `#[tokio::test(start_paused = true)]`; reference: `connect_retries_until_endpoint_appears` in `src-tauri/src/services/sidecar/ipc.rs`.
- **Pace a timing-dependent unit by parameter, not constant** — production passes the constant (`appdb`'s `runJanitor`).
- **A test seam is a parameter or a field, never a swapped package variable.** In Go, `agent/chat`, `kubestore` and `kubeconn` call `t.Parallel()` in every test; one that must touch process state (`t.Setenv`, `syscall.Umask`) stays serial and says why.

Two bounded waits are allowed, and each must say so in a comment:

- **A negative assertion** — a `select` on the tripwire channel versus `time.After`, the window a multiple of the (shrunk) cadence. Sample the baseline off the same channel, never by polling a counter.
- **Latency injected into the code under test** — a fake that pauses on purpose to make a race determinate. The test's own assertion path stays immediate.

## Commits, pull requests and issues

- **Commits are terse conventional commits**: `type(scope): subject` — `feat`/`fix`/`perf`/`refactor`/`test`/`docs`/`chore`, scope only when it adds information (`sqlite`, `edges`, `watch`), `!` for breaking. Subject imperative, lower-case, no period, ≤72 chars, says what the change does (`feat(edges): enqueue an edge's source when the declaration commits`). No body unless the why isn't obvious — then 1–3 plain sentences, no bullets; longer rationale is an ADR the body links.
- **Pull requests follow [`.github/pull_request_template.md`](.github/pull_request_template.md)**: keep `Summary` (why), `Key Changes` (what), `Checklist`. The title is a natural, capitalized title (not a conventional-commit heading) led by the change type's emoji — 🎣 bug fix, 🐋 new feature, 📜 documentation, ✨ general improvement.
- **A spec never reaches `main`.** Propose it as a PR titled `📜 Spec: …`, from [`.github/PULL_REQUEST_TEMPLATE/spec.md`](.github/PULL_REQUEST_TEMPLATE/spec.md) (`gh pr create --template spec.md`). Accepted, it merges into `wip/<topic>`; implementation PRs target that branch; a PR from it lands the work on `main` and deletes the spec. → [`docs/specs/README.md`](docs/specs/README.md), [ADR: keep specs off main and build them on a wip branch](../../docs/adr/2026-11-17-keep-specs-off-main-and-build-them-on-a-wip-branch.md).
- **An issue describing work to be done follows [`.github/ISSUE_TEMPLATE/task.md`](.github/ISSUE_TEMPLATE/task.md)**: keep `Summary` and `Done when`. Title imperative, capitalized, no emoji. A bug not yet understood uses `bug_report.md`; a request with no plan, `feature_request.md`.

## Security invariants

The whole picture is [`docs/security-model.md`](docs/security-model.md); each area's guide lists what an ordinary change there can break. Three hold everywhere:

- **Anything running in the webview holds the full cluster surface, and the shell behind it.** `graphql_query` forwards operations unexamined, so executing code can call every mutation, `approvalDecide` included. The CSP in `src-tauri/tauri.conf.json` is the containment.
- **The approval request is the user's eye, and the eye is the whole gate.** Approve is a click on the drawn request and nothing else. Adding an approval path, a grant path, or a way for the model to make a grant is a security change, recorded under `docs/security/`.
- **Cluster data, model output and command output are attacker-controlled text.** No HTML sink, control sequences stripped, every untrusted string drawn through `VisibleText`; the sidecar redacts Secret data at write time and never logs request data.
