# src-tauri — Tauri/Rust native host

The desktop app's native host (Tauri 2). It owns windows, the tray and menus, the Go sidecar's lifecycle, and bridges GraphQL from the webview to the sidecar over a Unix socket (named pipe on Windows).

Two parts have guides of their own, loaded when a file in their folder is read: [`linux/CLAUDE.md`](linux/CLAUDE.md) (the bwrap and pasta the Linux packages carry, their AppArmor profiles, sources and licenses) and [`src/updater/CLAUDE.md`](src/updater/CLAUDE.md) (the in-app updater and its signing keys). Open one before changing the scripts it lists.

## Distribution & updates

**Not distributed through the Mac App Store.** `release-desktop.yml` signs what it ships: a notarized `.dmg` with the sidecar signed inside, an `.msi` signed through SignPath, unsigned `.deb`/`.rpm` (Linux's only formats), and `SHA256SUMS` with a detached GPG signature. The app and its bundled sidecar (`externalBin`) are versioned and released together. → [ADR: Linux ships only the .deb and the .rpm](../docs/adr/2026-11-07-linux-ships-only-the-deb-and-the-rpm.md).

**macOS and Windows update in the app; Linux does not** ([`src/updater/CLAUDE.md`](src/updater/CLAUDE.md)).

**A release file is named `kubetail-desktop-<version>-<os>-<arch>.<ext>`**, all lowercase, with Go's words: `linux`, `darwin`, `windows`; `amd64`, `arm64`, and `universal` for the one macOS build. `<version>` is the SemVer, also for the RPM and MSI. The release attaches `kubetail-desktop-<version>-linux-{amd64,arm64}.{deb,rpm}`, `-darwin-universal.dmg`, `-darwin-universal.app.tar.gz` (the updater's), `-windows-{amd64,arm64}.msi`, `latest-<key id>.json` for each key in service (the files whose name has no version, since installed apps read their URLs), `kubetail-desktop-<version>.cdx.json`, `kubetail-desktop-<version>-embedded-sources.tar.gz`, `SHA256SUMS` and `SHA256SUMS.asc`, and its `release` job fails on any other set. Tauri names its files after `productName` (`Kubetail`); `release-desktop.yml` renames each as it collects it, the `.msi` only after SignPath has signed it, since SignPath's artifact configuration matches Tauri's name. **The `.deb`'s `Package:` and the `.rpm`'s `Name:` are `kubetail`**: Tauri derives them from `productName` and has no setting for either. → [ADR: release files are named kubetail-\<product\>-\<version\>-\<os\>-\<arch\>](../docs/adr/2026-11-08-release-files-are-named-kubetail-product-version-os-arch.md).

**Pick the version with `/release-version desktop`** (`.claude/skills/release-version/SKILL.md`). It reads the commits under `src/`, `src-tauri/`, `sidecar/` and `proto/` since the last `desktop/v*` tag, recommends the next SemVer version and the tag to push, and lists the manifests to set (`tauri.conf.json`, `Cargo.toml`, `package.json`). It tags and edits nothing. A release is cut by pushing `desktop/v<version>`, which runs `release-desktop.yml` and makes a draft release; write its notes with `/release-notes desktop desktop/v<version>` (`.claude/skills/release-notes`) before publishing it.

**A desktop version is `<x>.<y>.<z>` or `<x>.<y>.<z>-rc.<n>`**; `scripts/check-release-version.sh`, which `release-desktop.yml`'s `config` job and the skill run, rejects any other and derives the package versions. The deb, `.dmg` and app carry the SemVer. The RPM is Version `<x>.<y>.<z>`, Release `0.rc.<n>` (`1` for a final), bundled from the built binary by `tauri bundle`; the MSI is `<x>.<y>.<z>.<n>` (`<x>.<y>.<z>` for a final), set through `bundle.windows.wix.version`. → [ADR: desktop pre-releases are rc.N](../docs/adr/2026-11-06-desktop-pre-releases-are-rc-n-mapped-per-package-format.md).

**The Linux packages carry Kubetail's own bwrap and pasta**, at `/usr/lib/kubetail-desktop/`, with AppArmor profiles in the `.deb` and their sources in `kubetail-desktop-<version>-embedded-sources.tar.gz` ([`linux/CLAUDE.md`](linux/CLAUDE.md)). **A Linux `tauri build` without `make build-desktop-bwrap` and `make build-desktop-pasta` first fails.**

## Layout

- `main.rs` — thin; calls `lib::run()`.
- `app.rs` — **entry point** (`run()`), wiring alone: builds the app, registers plugins + commands, runs `setup` (spawn sidecar, menu/tray, background tasks), drives the event loop, installs the tray icon (and swaps its menu, `rebuild_tray_menu`: setting a real tray's menu needs GTK on Linux) and the Unix signal handler, and starts the auth-state watch and the wake sources. It resolves `paths::Folders`, installs the log subscriber, and hands `SidecarService::spawn` the bundled binary. It also holds the two commands only the real app can run: `quit` routes through `AppHandle::exit`, and **`open_account_url` names its own URL** (a command that opened whatever it was handed would be an exfiltration channel). Every item is inside a coverage marker, so a decision never lives here.
- `lib.rs` — module map, `invoke_handler()` (every command; a new one is also listed in `build.rs`'s `COMMANDS` and allowed by a capability), and the event loop's decisions as tested functions (`exit_requested`, `start_quit`, `exited`, `page_started`, `first_signal`).
- `commands.rs` — the other `#[tauri::command]` handlers. Keep thin — delegate to services.
- `cloud.rs` — the one home for the kubetail cloud base URL (tray and webview account menus).
- `host_file.rs` — **`host.json`**, the persisted-settings source of truth. Versioned JSON, all-`Option` patches (`HostFilePatch`) through the one `update_host_file` command; defensive reads, atomic writes. Reaches the webview via `window.__KUBETAIL_HOST__` and the `host-file-updated` broadcast, both fed from one read in `build_window`. Persistence only. Webview counterpart: `src/lib/host-file.ts`. It lives in `Folders::config`; `host_file::manage` places it in `setup`. → [ADR: host.json settings](../docs/adr/2026-08-09-host-json-settings.md), [ADR: host.json in the Kubetail config directory](../docs/adr/2026-11-21-host-json-lives-under-the-kubetail-config-directory.md). It is a *preference* in [`docs/persisted-data.md`](../docs/persisted-data.md): a layout change bumps `CURRENT_SCHEMA_VERSION` and updates its register row in the same commit. → [ADR: each persisted format carries its own version stamp](../docs/adr/2026-10-29-each-persisted-format-carries-its-own-version-stamp.md).
- `logging.rs`, `webview_log.rs`, `log_rotate.rs` — see Logging. `paths.rs` — the app's directories, a folder per kind on each platform (`layout`, tested on every OS), and the one place their leaf is resolved. → [ADR: a folder per kind](../docs/adr/2026-11-22-each-folder-kind-has-its-own-folder-on-every-platform.md). **The sidecar places its folders itself** from the same environment (`sidecar/internal/app/layout`); `sidecar/internal/app/layout/testdata/layouts.json` pins both layouts (`each_platforms_layout_is_the_fixtures`). The host makes its own folders and passes only `--runtime-dir`, and `--dev` for its profile (`cmd_args`). → [ADR: the sidecar places Kubetail's folders itself](../docs/adr/2026-11-23-the-sidecar-places-kubetails-folders-itself.md). **`Folders::make` follows each folder's links once, in `setup`**; callers take `&Folders`. On Windows no link may lead one out of the profile. A config folder that was itself a link keeps its target's mode. **A root holding `..` is refused** by name (`plain_root`) and fails the launch. → [ADR: each file in the platform's directory for its kind](../docs/adr/2026-09-27-kubetails-files-follow-the-platforms-directory-kinds.md).
- `state.rs` — `AppState` via `app.manage`. `shutdown` is a `CancellationToken` cancelled once on Quit; `quit` is where the quit is.
- `app_menu/` — **macOS-only** menu bar: File, and Edit, whose predefined items are what deliver ⌘C/⌘V/⌘X/⌘A/⌘Z to the webview. `app_menu/macos.rs` builds it, wiring alone; what an item does is `AppMenuAction` in `app_menu/mod.rs`, tested everywhere. Linux and Windows have none: the webview's `AppMenu` calls `new_window`/`quit`.
- `tray/` — tray icon/menu + the gRPC auth-state watch supervisor. `tray/mod.rs` holds the menu, the item actions (`TrayAction`, `run_action`) the menu for the stored account snapshot (`current_tray_menu`) and the watch (`watch_auth_state`, which takes the menu rebuild as a parameter), all tested on the mock runtime; Quit, Account Settings and the update item leave the app, so `app.rs` handles them; `tray/account_menu.rs` is the pure, unit-tested account section, hidden for the MVP behind `SHOW_ACCOUNT_SECTION` (the webview app bar likewise leaves out `AccountAvatar`). The tray does not surface kube-context.
- `icons/` — generated by `make generate-desktop-icons` from `src-icons/`; never edit by hand. The macOS tray draws `icons/tray.png` as a template image, so the menu bar recolours it; elsewhere the tray reuses the window icon.
- `dock_menu/` — the macOS Dock menu (New Window, Show Main Window) and the Quit reply, `applicationShouldTerminate:`. `dock_menu/macos.rs` patches both onto tao's delegate class, wiring alone; what an item does (`DockAction`) and the reply (`terminate_reply`) are in `dock_menu/mod.rs`, tested everywhere.
- `window_manager.rs`, `window_state.rs`, `error.rs` — see Windows below.
- `webview_profile.rs` — the webview's profile directory on Linux and Windows, `<state>/webview`, which `build_window` hands each window.
- `log_windows.rs` — see Log windows below. `window_title.rs` builds a log window's native title from the parts its page sends, each stripped as `src/lib/visible-text.ts` strips and capped.
- `quit.rs` — the quit state (*running*, *waiting*, *done*); see Graceful shutdown below.
- `os_theme.rs` — `prefers_dark()` before any window exists (macOS, Windows; not compiled on Linux). What each reading means is a free function compiled everywhere. Every failure degrades to light.
- `services/sidecar/` — sidecar process + IPC (below).
- `updater/` — the in-app updater ([`src/updater/CLAUDE.md`](src/updater/CLAUDE.md)).
- `wake/` — fires the sidecar's `Poke` on wake-from-sleep and network-return. `wake/core.rs` is the pure, unit-tested heart (`classify`, `run_coalescer` 3s debounce); the platform sources are thin FFI glue, and **the "which integer means online" mappings stay in `core.rs`** so they test everywhere. Failures are logged and swallowed. → [ADR: poke resync fan-out](../docs/adr/2026-08-09-poke-resync-fanout.md).

## Logging

**Text on stderr always, plus JSON files** (`.json().flatten_event(true)`), rotated by size (`log_rotate.rs`), in `~/Library/Logs/Kubetail{,-dev}` on macOS, `<state>/logs` on Linux and Windows. **Not `app_log_dir`**: bundle id, no dev leaf. → [ADR: JSON logs rendered by the host](../docs/adr/2026-09-08-json-logs-rendered-by-the-host.md).

**The subscriber is built in two steps**, since the log directory needs an `AppHandle`: `logging::process_subscriber` composes the registry, an empty `reload::Layer`, the `EnvFilter` and stderr, which `app.rs` installs; `logging::install_file_layer` swaps the file layer in.

- **The reload layer goes first, directly on the registry**, or its handle's type cannot be written.
- **The swap is the first thing `setup` does, after `Folders::make` and before `SidecarService::spawn`**, so startup reaches the file.

**The host writes `main.log` and `webview.log`, split by target**: `webview.log` holds every record carrying `logging::WEBVIEW_TARGET`. `main.log` takes the sidecar's forwarded lines only in a release build (`is_host_log`). Stderr carries everything. **The split is made by the writers, never a per-layer filter** — `reload` cannot carry a `Filtered` layer. → [ADR: webview records get their own log file](../docs/adr/2026-09-08-webview-records-get-their-own-log-file.md).

**The terminal format is `TerminalFormat`** (`logging.rs`), a tag per process plus the host's module. **The first `#[instrument]` in the host needs span rendering added there.** Colour is guarded on `Writer::has_ansi_escapes`; a debug build always colours, and `NO_COLOR` turns it off.

**Failing to open a log never stops the app** — it runs on stderr alone.

**The log file is flushed by hand.** `App::run` ends with `std::process::exit`, so no `Drop` runs: `RunEvent::Exit` calls `AppState::flush_log` **last**, and nothing logged after it reaches the file. Tests drop the guards before reading a file.

**Every message is one line.** `logging::sanitize_text` escapes control characters and caps the result after escaping, on a character boundary. Every webview string goes through it, and every line off the sidecar's pipes.

**The sidecar writes `sidecar.log` itself**, in its layout's log folder, the host's own; `spawn` passes only `--log-stderr`, in debug. The host logs the spawn with that folder, `READY` and the exit. **`logs.rs` parses the sidecar's JSON pipe lines** (`parse_record`) and re-emits each under `logging::SIDECAR_TARGET`, extra fields folded into the message as `key=value`. **A line that will not parse passes through at `warn`** (a Go panic). **A message is sanitized before it is emitted**, since `serde_json` decodes its control characters (`a_forwarded_message_stays_on_one_line`). → [ADR: two processes, two log files](../docs/adr/2026-09-08-two-processes-two-log-files.md).

**Webview errors reach `webview.log`** through `webview_record_error` (`webview_log.rs`). The command reads the label off its `tauri::Webview` argument, never the payload, and hands everything to `record_from`. `stack`, `componentStack` and `context` ride together under **`reported`**, never flattened into host fields; the sanitized message is the one top-level page value. Severity is derived from the source. **The host bounds what it writes**: `MAX_*_BYTES` per field, truncating before serializing, never cut JSON. The command is `async`, off the main thread.

**Each webview is rate limited** by `AppState::webview_log`, a `Limiter` keyed by label (`LimiterConfig::DEFAULT`): token buckets, an `error`-only reserve, and suppression by signature. Nothing is lost silently — a summary names what was withheld. `WindowEvent::Destroyed` evicts the entry; `PageLoadEvent::Started` writes a marker. Labels are `main`, `window-N` or `logs-N` (`WindowManager::next_label` and `next_logs_label`, one counter, never reused). **The globs in `capabilities/default.json` (`main`, `window-*`) and `capabilities/logs.json` (`logs-*`) must admit every label minted**, or the window silently gets no permissions.

**The level is `KUBETAIL_LOG_LEVEL` only.** A runtime setting would need its own `reload::Layer` around the `EnvFilter`.

## Windows

All chrome decisions live in `build_window` (`window_manager.rs`); `tauri.conf.json` declares **no windows** (a unit test pins this). Per-platform: macOS native decorations with Overlay title bar + repositioned traffic lights; Windows frameless-opaque; Linux frameless-transparent (the webview's `WindowFrame` paints border/shadow). → [ADR: per-platform window chrome](../docs/adr/2026-08-09-per-platform-window-chrome.md).

Traps that bite:

- **Building a window is a blocking call — use the blocking pool.** `WebviewWindowBuilder::build()` parks its thread until the webview exists; on the main thread that deadlocks Windows. Every off-main-thread entry point uses `tauri::async_runtime::spawn_blocking`, never `spawn` (which would park a worker serving `graphql_query`). Such commands take `AppHandle`, and `log_window_open` the caller's `Webview` beside it. The macOS-only `app_menu/macos.rs`/`dock_menu/macos.rs` call from the main thread — fine there.
- **Windows are visible from creation, painted with the resolved scheme at t0** (`background_color_for`). There is **no reveal step** — do not reintroduce one. On macOS this depends on **`tauri/macos-private-api`** (mirrored by `app.macOSPrivateApi`); `background_color` must always be passed on opaque platforms, and the document must stay opaque. → [ADR: first-paint theming](../docs/adr/2026-08-09-first-paint-theming.md).
- **A new window is sized to its monitor** (`fit_size`: its spec's size, at most 85% of the work area per side, never below 600×400) **and cascades** (`cascade_position`), positioned explicitly on all three platforms. An app window takes the size of the app window it anchors on unless that one is minimized, fullscreen or maximized. The monitors come through the `Monitors` trait: `app.rs`'s `AppMonitors` reads the real runtime's, and tests pass `testutil::OneMonitor`, since the mock runtime has none.
- **The main window reopens at its saved frame** (`window_state.rs`), maximized if saved so, while the frame still `fits` a connected monitor (no larger than its work area, title bar reachable); else at its default size, centered on the primary. **Log windows cascade in a group per app window** (`LogGroups`, `next_in_group`): one steps off its group's last window (the one last placed, moved, resized or focused), reopens where that was when none of the group is open, else steps off its app window at the saved log size. It joins its group when placed, before its build, so a quick second open steps off it; never maximized. Frames are in the builder's logical px. `window_moved` reads a frame on every move and resize; a minimized or fullscreen window is skipped, and a frame that `covers` its work area counts as maximized, as Windows reports a maximize's move before the window reads maximized. The main frame and the log size are written when such a window is destroyed and on exit; groups stay in memory. `make clean`/`clean-data` reset the dev build's file.
- The pure helpers (`traffic_light_position`, `background_color_for`, `fit_size`, `fits`, `covers`, `cascade_position`) compile on every platform so CI covers them. Traffic-light constants stay in sync with the webview's: the bar heights with `app-bar/bar.tsx` and `log-window/bar.tsx`, the gutter with `traffic-light-gutter.tsx`'s `TRAFFIC_LIGHT_GUTTER`, which both bars draw. **The position's `y` is not the gap above the buttons** — they keep an 8pt inset from the container's bottom, so centring is `y = (bar - button) / 2 + 8`, which `traffic_light_position` derives. `LIGHT_BACKGROUND`/`DARK_BACKGROUND` track `@kubetail/ui`'s `--background` by eye.

## Log windows (`log_windows.rs`)

A log window (`logs-N`) shows one tool call's logs, paired to the app window that opened it. → [ADR: a log window belongs to one app window](../docs/adr/2026-11-04-a-log-window-belongs-to-one-app-window-and-the-host-keeps-the-pair.md), [log windows](../docs/security/2026-11-04-log-windows.md). `LogWindows` (on `AppState`) holds the pair behind one `Mutex`: each app window's **page**, a number minted by each `log_window_subscribe` with the channel it subscribed with, and each log window's entry. A page ends when its window is destroyed or its page reloads; **every app-window command names its page** and is refused on an ended one. **Every command reads the caller's label off its `Webview`** and checks the label's kind, beside the capability.

- **An entry is `Building`, then `Live`.** `log_window_open` reserves under the lock, then builds on the blocking pool through `open_log_window`; a second open on the call waits on the first's outcome (a `tokio::sync::watch`). A close or a destroy during the build removes the entry and answers its waiters with `AppError::Cancelled` at once; the build then finds no entry and destroys its window. The app window sees only `Live` entries: no `snapshot` or frame names a `Building` one until `opened`.
- **The lock guards the maps and the channel sends, and nothing else.** Every frame is sent under it, with the change it reports, so `snapshot` comes first and nothing races it. Transitions (`reserve`, `built`, `failed`, `close_all`, `destroyed`, `page_started`, `focused`) return what the wiring does next; windows are built, surfaced and destroyed after the lock is released.
- **The host destroys the log windows it closes, never `close()`s them.** A page can cancel `CloseRequested`; a log window must not outlive its app window. An app window's `Destroyed` destroys its log windows (`lib.rs::window_destroyed`).
- **A log window's page load steps its generation**, and `log_window_viewport` refuses a push from an earlier one. The push is bounded (256 KiB) and opaque past `generation` and `grep`: its `viewport` is the page's view and selection, which the host forwards to the paired app window unread.
- `app.rs` forwards `Focused(true)` and `Destroyed` to `lib.rs`'s `window_focused` and `window_destroyed`; `page_started` reaches the pair too.

## Sidecar IPC (`services/sidecar/`)

The sidecar is a bundled child process (`service.rs::spawn`) on a per-instance socket picked pre-spawn (`ipc.rs`), inside an owner-only runtime directory (`paths.rs::runtime_dir`: `$XDG_RUNTIME_DIR/kubetail` on Linux, else a `0700` per-uid temp folder this user owns, `Kubetail\run` on Windows).

- **Stdout carries the readiness protocol and nothing else**: `READY `, or `FATAL <reason>` when the sidecar cannot compose its app, which ends readiness with that reason for `ready()` to return and the start screen to show (`stdout_line`, `wait_ready`). Everything else is forwarded by `logs.rs`.
- **`SidecarService::ready()` waits on `READY_BUDGET` (30s), not `DEFAULT_CONNECT_BUDGET`**, since the sidecar runs the login shell before it binds. `ReadyGate` does not retry, so one timeout is an error screen.
- **Shutdown**: dropping the child closes stdin → EOF → the sidecar runs its stop sequence (`sidecar/CLAUDE.md`). Closing the last window does **not** exit the app; only Quit (or a Unix signal, `app.rs::spawn_signal_handler`) does.

- **Queries/mutations**: one fresh HTTP/1 connection per call (`graphql/query.rs`), 30s `REQUEST_BUDGET`.
- **Subscriptions**: one SSE connection per subscription (`graphql/subscribe.rs`) into `{type,payload}` channel envelopes. Graceful completion → `{"type":"complete"}`; abnormal drop → `{"type":"closed"}` — read off body framing, since gqlgen's `event: complete` is data-less. **`{"type":"open"}` is sent only after the 200**, never on a failed dial or the ack; the frontend keys its resets on it. → [ADR: transport-status generation](../docs/adr/2026-08-09-transport-status-generation.md). `FrameSink` is the delivery seam.
- **The host relays subscriptions without knowing their kind**; its own one is `AuthStateWatch`, a state watch ([`docs/data-access.md`](../docs/data-access.md)).
- **gRPC** (`grpc.rs`): auth (state watch/login/logout) + resync poke, over the same socket via h2c, one cached `Channel` re-dialed on drop. Bindings from `build.rs` over `proto/`. → [ADR: single-socket h2c from the standard library](../docs/adr/2026-10-26-single-socket-h2c-from-the-standard-library.md).

## Graceful shutdown (`AppState::shutdown`)

Quit cancels the app-wide `CancellationToken` before `SidecarService::graceful_shutdown`. Every app-lifetime background task holds a clone and `tokio::select!`s on `shutdown.cancelled()` in each loop/await. **New background tasks must follow the same pattern.** Per-subscription teardown is the `oneshot` cancel table in `graphql/subscribe.rs`, keyed by op id and tagged by webview.

**The wait for the sidecar never runs on the event loop**, where it would freeze the app for up to `SIDECAR_SHUTDOWN_GRACE` (23s, above the sidecar's 20s `shutdownBudget`). The quit state is `AppState::quit` (`quit.rs`):

- **The first `ExitRequested` with a code** moves it from *running* to *waiting*, cancels `shutdown`, prevents the exit, hides every window, and starts a thread that waits, moves to *done*, and calls `exit` again (`lib.rs::start_quit`).
- **Every `ExitRequested` while *waiting* is prevented.** Every Quit path reaches the same `app.exit(0)`, and letting a second Quit through would run `RunEvent::Exit` and kill the sidecar mid-stop. A SIGTERM during the wait is swallowed (the signal task has returned), and a second launch is one more refused ask.
- **No window opens once a quit has begun.** Every path that opens or shows one ends in a `WindowManager` method: `new_window`, `show_main_window`, `open_log_window` or `surface_window`. Each checks the `shutdown` token it holds on entry, then queues a second check on the main thread behind what it presented, even when a step of it failed, which hides a window whose build or show was still in flight when the quit began. A new path needs no check of its own; a refused ask logs a `warn`.
- `RunEvent::Exit` keeps the kill as the backstop and warns when it was needed; an exit that is not code 0 with no signal is logged at `warn`.
- A macOS logout skips all of this: the host answers `NSTerminateNow` (`dock_menu`) and the kill runs at once.

## Security invariants

Full picture: [`docs/security-model.md`](../docs/security-model.md). What the host owns:

- **The webview never navigates off the app origin.** `build_window` installs `on_navigation(is_app_origin)` — an allowlist ending in `false` (app origin, `about:blank`, the dev server in debug) — and `on_new_window`, always `Deny`. A feature that needs an external URL needs a host command (the opener plugin, Rust-side). Verified by hand, not by a test.
- **The webview is trusted by custom host commands, and a window calls only what its capability allows.** `build.rs`'s `COMMANDS` lists every command (`AppManifest::commands`); tauri-build writes an `allow-<command>` permission for each, underscores as hyphens, into the gitignored `permissions/autogenerated/`, and Tauri denies a command no capability allows. `every_command_is_in_the_app_manifest` holds the list to `invoke_handler`. `capabilities/default.json` grants the app windows the window getters, the devtools shortcut (`core:webview:default`), event listen and unlisten, the window controls and thirteen commands — no emit, so a page cannot send an event as the host; no menu, tray, image, resources, path or app API; no shell, opener or updater grants. `capabilities/logs.json` grants a log window the same core set, the GraphQL commands, `webview_record_error` and its four log-window commands, and nothing that opens a window, changes a preference, quits or opens a URL. Pinned by `default_capability_grants_what_the_app_window_calls` and `logs_capability_grants_the_viewer_and_nothing_else`. Add a permission only when a call site needs it, scoped as narrowly as the plugin allows.
- **Every dial checks who answered.** An address and the pid that must serve it travel together as one `ipc::Target`. The pid is read from the kernel (`peer.rs`, `LOCAL_PEERPID` on macOS), published by `spawn`, cleared when the child exits; `None` or an unreadable peer refuses. Pinned by `connect_refuses_a_peer_that_is_not_the_expected_process` and `query_refuses_a_server_that_is_not_the_sidecar`.
- **Nothing the sidecar needs may come from this process's environment**, which it inherits. Every endpoint is passed by `cmd_args` from constants in `service.rs`; new configuration goes the same way. Kubetail's folders are the stated exception: the sidecar reads their roots from the environment, as the host does, and `layouts.json` holds the two layouts to one answer. `KUBETAIL_*` overrides work only in a `-tags debug` sidecar (`make build-desktop-sidecar-dev`).
- **A webview's subscriptions are torn down by the host** (`lib.rs::cancel_webview_subscriptions`) on `PageLoadEvent::Started` and `WindowEvent::Destroyed`, since a reload runs no JS teardown. Pinned by `cancel_webview_drops_only_that_webviews_subscriptions`.
- **Structured text from the webview never becomes a host log field or a second log line** — `reported` alone, sanitized, capped and paced. Pinned by `page_supplied_fields_ride_under_one_key` and the sanitizer tests.
- **The macOS entitlements are exceptions.** `disable-library-validation` and `allow-unsigned-executable-memory` remain unverified pending signed macOS testing (H-3). Don't add an entitlement without saying in `entitlements.plist` what needs it.

## Conventions

- **No `unwrap`/`expect`** — `#![warn(clippy::unwrap_used)]`. Poisoned mutexes: `.lock().unwrap_or_else(|p| p.into_inner())`.
- **Errors** (`error.rs::AppError`): transport failures cross the command boundary as `AppError::Io` so urql sees a `networkError` and retries. **HTTP non-2xx is NOT an error** — return `Ok(GraphqlResponse{status, body})`.
- Menu/tray callbacks are sync and can't return errors — log failures; for async work `tauri::async_runtime::spawn`.
- Off-main-thread menu mutation: queue with `app.run_on_main_thread(...)`.

## Tests & checks

- Inline `#[cfg(test)] mod tests` with `#[tokio::test]`; UDS/pipe fixtures via `interprocess`. Factor pure logic into free functions to unit-test it.
- **Code that holds an `AppHandle` is generic over `R: Runtime`**, so tests run it on Tauri's mock runtime (`tauri`'s `test` feature, dev-only). `testutil.rs` builds the mock app: every command registered, app directories under a scratch directory, and `SidecarService::without_process`. Tauri's directory override does not reach the platform roots, so `Folders::make` takes `paths::Roots` and a test passes `testutil::folders(scratch)`, made over `testutil::roots(scratch)`. `SidecarService::spawn` takes the command it runs, so a test spawns `sh` (`testutil::script_sidecar`). `services/sidecar/testutil.rs` serves fake gRPC services (`FakeGrpc`, from `build.rs`'s server stubs) that `SidecarService::dialing` reaches. The mock has no monitor, so `WindowManager` takes its monitors as a parameter (`testutil::OneMonitor`). `AppHandle::exit` is unimplemented there, so a quit path takes its exit as a parameter (`lib.rs`'s `exit_requested`). AppKit builds menus on the main thread alone, which no test runs on, so menu-building tests are `cfg(not(target_os = "macos"))`, and the macOS menu bar's and Dock menu's construction sit in ignored files.
- **A test reads its logs through `logging::captured` or `capture_thread`.** The first capture sets a global default that writes nothing, so a callsite another thread reaches first stays live for the capture; no test sets another global default.
- **The suite runs under both profiles.** A PR tests the dev profile; a push to `main` also builds and tests the release profile (`ci.yml`'s `rust-test-release`) on `release-desktop.yml`'s runners, Linux on Ubuntu 22.04. A test of a `cfg!(debug_assertions)` branch asserts against `cfg!(debug_assertions)`, so each profile pins its own half (`is_app_origin`'s). `cargo test --release` runs it locally. → [ADR: main builds and tests the release profile](../docs/adr/2026-11-10-main-builds-and-tests-the-release-profile.md).
- **Coverage is measured in `coverage / Rust (<os>)`** (`cargo llvm-cov`, one runner per OS) and gated by `coverage / Gate`; the root `CLAUDE.md`'s *Testing conventions* has the markers for a region no test can reach. The job runs `tools/coverignore -lcov` over `cargo llvm-cov`'s report before the upload. Where a marker's reason is the real runtime, say what of it the line needs ("needs a real window system's tray"). `app.rs` and `wake/macos.rs` are marked item by item. A file with no line a test can reach — the entry point, `app_menu/macos.rs`, `dock_menu/macos.rs`, the OS glue in `wake/linux.rs` and `wake/windows.rs` — is listed in `.github/codecov.yml`'s `ignore` instead. An `async` command's `#[tauri::command]` line counts its last argument's parse failure, which `new_window`'s lone `AppHandle` cannot produce, so that line is marked.
- `make lint-desktop` runs `cargo fmt --check`, `make vet-desktop` `cargo clippy --all-targets -- -D warnings`.
- **The compiler is pinned** in `rust-toolchain.toml`; CI reads the channel from it. rustup resolves it from the working directory — **a `rustup`/`cargo` call from the repo root needs `working-directory: ./src-tauri`**, or it silently uses the default toolchain.
